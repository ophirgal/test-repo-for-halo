# Feature Specification Document — SCRUM-120: Offline link checker for the docs site with a JSON and Markdown report

> Status: final specification (READY_FOR_SPEC). On 2026-11-23 the developer told the intake to make the open decisions itself and not to ask further. The intake therefore adopted its own recommendations as D1–D7; they are recorded as decisions in §3, §5 and §8.

## 1. Feature Overview

**What is being built.** A new, standard-library-only Python command, `python -m linkcheck <dir>`, that crawls every HTML page under a directory, extracts the links that pages make with `href`/`src` on `a`, `link`, `img` and `script`, and reports broken internal links, missing anchors, links escaping the scanned root, empty links and undecodable pages — as one terminal line per finding, an exit code, and optional JSON and Markdown reports. External links are listed, never fetched.

**Problem.** Broken links in the repository's static docs site (`docs/`) are found today only by readers. Nothing checks them before publishing, and the check must work without network access.

**Target user.** A developer who maintains the docs site under `docs/` and runs the check from the terminal (and, later, in CI) before publishing.

**Grounding in the repository** (`ophirgal/test-repo-for-halo`, target branch `main`, at `51b3688`):
- `docs/index.html` and `docs/jungle.html` exist, as the story's pre-conditions say. Neither page contains a single `href` or `src` attribute today (both are self-contained, with inline styles), so the real-site run in criterion 13 checks 2 pages and 0 links.
- No `linkcheck/` package and no `tests/` directory exist yet; the existing Python files (`serve.py`, `smoke_test.py`) are standard-library-only, which matches the story's no-dependency rule.
- The repository has no CI workflow (no `.github/`), no `CLAUDE.md`/`AGENTS.md` and no `.factory/` folder, so no repository gate or rule collides with this story.

## 2. Goals & Non-Goals

### Story context

The story adds a new, stdlib-only Python package `linkcheck` at the repository root with its tests under `tests/`, in three dependent work items: the HTML link extractor (t1), the resolver and checker (t2) and the command line with its reports (t3). Only `href` and `src` attributes of `a`, `link`, `img` and `script` elements count. External links (any scheme other than none or `file`) are listed but never fetched. Fragment links (`#id`) must resolve to an element carrying that `id` (or an `a` with that `name`) in the target page. Pages are UTF-8; a page that fails to decode is itself a finding. Out of scope: fetching external URLs, JavaScript-generated links, CSS `url()` references, any third-party dependency, changes to any existing file except README.md.

### Goals

- A developer can run `python -m linkcheck docs/` offline and learn, per broken link, the file and line that holds it.
- The exit code distinguishes clean (0), findings (1) and usage errors (2), so a CI job can fail on a broken link.
- Machine-readable (JSON) and human-readable (Markdown, CI job summary) reports, deterministic across runs.
- Running against the repository's own `docs/` exits 0, and README.md documents the command.

### Non-Goals

- Fetching or validating external URLs (any scheme other than none or `file`).
- Links generated by JavaScript; CSS `url()` references; any attribute other than `href`/`src`; any element other than `a`, `link`, `img`, `script`.
- Any third-party dependency.
- Changing any existing file other than README.md (so `docs/*.html`, `serve.py` and `smoke_test.py` stay untouched).
- Adding a CI workflow to the repository (decided, §8 D5): README.md shows how a CI job runs the command instead.
- Making the real-site run non-trivial: `docs/` keeps its current pages, which hold no links (decided, §8 D6).

## 3. Functional Requirements

**Link extraction (t1)**
- FR1 — `extract_links(path)` returns the page's links in document order as `Link` values with `target` (str), `line` (1-based int) and `kind`: `anchor` (`a href`), `image` (`img src`), `stylesheet` (`link href`) or `script` (`script src`).
- FR2 — Targets are HTML-unescaped (e.g. `&amp;` → `&`) and trimmed of surrounding whitespace.
- FR3 — An empty `href=""` (after trimming) is not a link: it is a finding `empty-link`.
- FR4 — A file that is not valid UTF-8 raises `PageDecodeError`, naming the path and the byte offset. At the site level an undecodable page is itself a finding of kind `decode-error`, whose line is the line of the first bad byte and whose target is `byte <offset>`. The page counts in `pages`, its links are not checked, and the run exits 1.

**Resolution and checking (t2)**
- FR5 — `check_site(root)` checks every HTML page under `root` and returns its findings plus counts of pages, links and external links.
- FR6 — A link with any scheme other than none or `file` is external: counted and listed, never fetched, never a finding.
- FR7 — A relative link resolves against its page's location; a target that does not exist is a finding `missing-target` carrying the source page, line and the resolved path relative to the root.
- FR8 — A link that ends in `/` resolves to that directory's `index.html`, and is broken only when that file is missing.
- FR9 — A fragment (`page.html#id`, or bare `#id` for the same page) must match an element with that `id`, or an `a` with that `name`, in the target page; otherwise a finding `missing-anchor`.
- FR10 — A link that resolves outside the root is a finding `outside-root`, and the file it points at is never read.
- FR11 — A root-relative link (`/page.html`) resolves against the scanned root, the way `serve.py` serves `docs/` at `/`. A `file:` URL resolves as a filesystem path; when it leaves the root it is an `outside-root` finding and is never read.
- FR11a — `href="#"` (an empty fragment) refers to the page itself and is not a finding.

**Command line and reports (t3)**
- FR12 — `python -m linkcheck <dir>` prints one line per finding as `path:line: kind: target`, and exits 0 with no findings, 1 with findings, 2 on usage errors (e.g. a missing directory).
- FR13 — `--json out.json` writes `{"pages":n,"links":n,"ignored":n,"external":[...],"findings":[...]}`. Each finding is `{"path","line","kind","target"}` and each external entry is `{"path","line","target"}`. Both lists are sorted by path, then line, and the file is byte-identical across runs on the same input.
- FR14 — `--markdown out.md` writes a summary table and one section per page that has findings, suitable for a CI job summary.
- FR15 — `--ignore PATTERN` (repeatable) drops links whose target matches the fnmatch pattern before checking; the report counts them as ignored (`"ignored"` in the JSON, an "Ignored" row in the Markdown summary).
- FR16 — README.md documents the command.

## 4. User Experience & Behavior

- **Clean run.** `python -m linkcheck docs/` prints no finding lines and exits 0.
- **Broken links.** One line per finding, `path:line: kind: target` (e.g. `guide/intro.html:12: missing-target: guide/setup.html`), then exit 1. The developer can jump from the line straight to the file and line.
- **Usage error.** A missing or unusable directory argument exits 2 with a usage message; no reports are written.
- **Reports.** `--json` gives tooling a stable, sorted document; `--markdown` gives a table and per-page sections that read well when pasted into a CI job summary. Both are optional and can be combined.
- **Offline.** No run ever makes a network request, whatever the pages link to.
- **Finding kinds the user sees:** `empty-link`, `missing-target`, `missing-anchor`, `outside-root`, `decode-error`.

## 5. Acceptance Criteria

1. Scenario 1 — Happy path: Given an HTML page with three `a href`, one `img src` and one `link href`, When `extract_links(path)` runs, Then it returns five `Link` values in document order, each with `target` (str), `line` (1-based int) and `kind` (`anchor`, `image`, `stylesheet` or `script`).
2. Scenario 2 — Boundary: Given `href` values with surrounding whitespace, HTML entities (`&amp;`) and an empty `href=""`, Then targets are unescaped and trimmed, and the empty one is reported as a finding `empty-link` rather than a link.
3. Scenario 3 — Error: Given a file that is not valid UTF-8, Then `extract_links` raises `PageDecodeError` naming the path and the byte offset.
4. Scenario 4 — Happy path: Given a site where every relative link points at an existing file and every fragment at an existing id, When `check_site(root)` runs, Then it returns no findings and counts pages, links and external links.
5. Scenario 5 — Broken file: Given `a href="missing.html"`, Then one finding `missing-target` carries the source page, line and the resolved path relative to the root.
6. Scenario 6 — Broken anchor: Given `a href="other.html#nope"` where other.html has no element with id `nope`, Then one finding `missing-anchor`; a bare `#top` is checked against the same page.
7. Scenario 7 — Escape: Given a relative link that resolves outside the root (`../../etc/passwd`), Then a finding `outside-root` and the file is never read.
8. Scenario 8 — Directory links: Given `href="guide/"`, Then it resolves to `guide/index.html` and is broken only when that file is missing.
9. Scenario 9 — Exit codes: `python -m linkcheck <dir>` exits 0 with no findings, 1 with findings, 2 on usage errors (missing dir), printing one line per finding as `path:line: kind: target`.
10. Scenario 10 — JSON report: `--json out.json` writes `{"pages":n,"links":n,"ignored":n,"external":[...],"findings":[...]}`, each finding `{"path","line","kind","target"}` and each external entry `{"path","line","target"}`, both lists sorted by path then line, deterministic across runs.
11. Scenario 11 — Markdown report: `--markdown out.md` writes a summary table and one section per page with findings, suitable for a CI job summary.
12. Scenario 12 — Ignore list: `--ignore PATTERN` (repeatable, fnmatch on the target) drops matching links before checking and the report counts them as ignored.
13. Scenario 13 — Real site: run against the repository's own `docs/` directory, the command exits 0, and README.md documents the command.
14. Scenario 14 — Scope boundary: Given a page with `a href="https://example.com/x"`, a CSS `url()` reference and a link built inside a `<script>` body, When the command runs with no network access, Then the `https` URL is listed in `external`, nothing is fetched, the CSS and script-built references are not counted as links, and the command exits 0.
15. Scenario 15 — Root-relative and `file:` links: Given `a href="/other.html"` on a page in a subfolder, Then it resolves against the scanned root and is broken only when `<root>/other.html` is missing; Given `a href="file:///etc/passwd"`, Then a finding `outside-root` and the file is never read.
16. Scenario 16 — Undecodable page in a site: Given a site with one page that is not valid UTF-8, When the command runs, Then it prints `path:line: decode-error: byte <offset>` for that page, counts the page in `pages`, checks none of its links, and exits 1.
17. Scenario 17 — Empty fragment: Given `a href="#"`, Then no finding is reported.

The Markdown summary gets an "Ignored" row. This rewords criterion 10; the other twelve original criteria stand word for word.
