Choices made in this screen set

  • Look, layout and copy carry over unchanged from concept A: system font, white page, label + field + Send on one row (also at 360 px), ruled list with time on the right on desktop and above the text on a phone.
  • No loading state is drawn: the inventory names none — the form posts and the server returns the full page (structure, open branch 4).
  • Errors: the hint line under the field is replaced by the error (red text on a pale red band with an icon), the field gets a 2 px red outline and aria-invalid, and the visitor’s text stays in the field (AC 3). The error is announced with role="alert".
  • The two error screens are drawn over a full list. When a refused send happens on an empty guestbook, the same form and error sit above the “No messages yet” line of screen 02 — no separate page, as the inventory names it a variant only.
  • Every message is rendered as escaped text with dir="auto" and overflow-wrap: anywhere, so Hebrew reads right to left, markup shows literally, and a 200-character word wraps inside the 360 px column (AC 5, R7).
  • Build note for SCRUM-126: the form is method="post" action="/guestbook" in the real page; here it targets screen 03 so the set can be clicked. The “Back to all screens” footer is for review only and is not part of the built page.
  • Home and “jungle” are not drawn or changed, and they do not link to the guestbook (AC 6).
