Concept A · Compact — the /guestbook main path

A dense, plain page in the style of the site's home page: the message field and Send button share one row, and the 20 messages sit in a ruled list with the send time beside each one. A visitor opens the guestbook, writes one line and sends it; the page comes back with their message on top.

Each screen is shown as a desktop browser (1280×800) with a phone overlapping its corner, both at the same scale. The phone is 360 px wide, not 390, because the story's acceptance criterion 2 asks for 360 px with no sideways scrolling and no zoom.

Choices made in this prototype

This concept

  • Form: label, then the field and the Send button on one row (also at 360 px).
  • List: one ruled row per message; time on the right on desktop, above the text on a phone.
  • Density: ~20 messages fit in about two desktop screens.

Shared by both concepts

  • Look follows the site's home page (docs/index.html): system font, white page, black text, no logo or navigation. Home and “jungle” are not touched and do not link here.
  • English page text; each message uses its own direction, so Hebrew reads right to left (structure, open branch 1).
  • Single-line field, no character cap and no live counter, so the “too long” error can be reached (open branches 2–3).
  • No loading state: Send posts and the full page returns (open branch 4). Here Send is a link to page 02.
  • Time as 2026-11-24 08:15, 24-hour, muted (open branch 5). No sender name.
  • No success banner: the visitor's message at the top is the confirmation.
  • The list already shows the edge content: a 200-character message with no spaces (wraps) and <b>שלום</b><script>… shown as plain text.
