New Performance tabs: clickable prototype

This prototype walks the main paths of the approved structure for the two new Performance tabs. A Harel or McKinsey stakeholder opens Performance from Halo's menu and lands on Engagement & Adoption: active users with the per-team and per-person tables, lines of code, the stories funnel and stories per week. From there they change the date range, or switch to Scale: human review score, factory quality with post-mortem detail, rating history, delivery quality, the AI judge, flow completion, time to converge and cost. On Scale they narrow the flow sections by Epic and Mode, and open a post-mortem report. Every page shows realistic sample figures for 6 Oct – 3 Nov 2026, compared with the 29 days before.

Screens

  1. Halo navigation — Performance: Halo's menu, with Performance as the way in.
  2. Engagement & Adoption (default): the default tab, with the date range as its only filter.
  3. Date range picker, opened from Engagement & Adoption: Apply or Cancel return to the tab.
  4. Scale: every Scale section in the order of the requirements doc, with the Epic and Mode filters unset.
  5. Date range picker, opened from Scale: the same control, returning to Scale.
  6. Scale — Epic and Mode filters: choose an epic and a mode, then Apply.
  7. Scale — filtered by Epic / Mode: the flow sections show Claims intake modernisation · Advanced. Human Review Score and Rating history stay unchanged and are labelled "not filtered".
  8. Post-mortem report detail: a report row opened in place inside Factory quality, showing what went well, what went wrong and what to change next time.

Choices made in this prototype

  • Only the main paths are drawn. The loading, error, empty-period and "people data not available" states are the Design step's work. One exception: on Scale, average time per judge run and critiques that led to a revision show a dash with "not available yet". Halo does not record them today (R7), so that is how Scale will look at launch.
  • Old links have no page. In the structure, an old Performance link redirects to Engagement & Adoption, and an old Cost & Usage, Factory Performance or Velocity link redirects to Scale. Neither redirect has a screen of its own.
  • Date range: a start and an end date, with no presets (open branch 1, simplest choice). There are no scripts, so Apply and Cancel both return to the tab and the figures stay as they are. The date range is shared by both tabs. Epic and Mode exist only on Scale (D13).
  • Tab switching: the Scale tab always opens Scale unfiltered here. In the product, Epic and Mode stay set when you come back to Scale (open branch 2, simplest choice).
  • Clearing a filter: on the filtered page, the × on each chip clears that filter and returns to unfiltered Scale. Change reopens the filter panel.
  • Post-mortem reports open in place: the row expands and Close collapses it (open branch 4, simplest choice). Every row in the list opens the same sample report (CLM-142, Delivery), and the report is always shown in the unfiltered Scale page.
  • Partial weeks: weeks run Sunday to Thursday. Partial weeks at the edges of the period are hatched bars, or shaded columns with hollow points on line charts, and are labelled "partial" under the axis. Every chart names both axes.
  • Headline figures show the change against the previous 29 days. Green means better and grey means neutral: cost and run counts going up are shown as neutral, not as bad.
  • Flows cost table: sorted by cost, highest first. Every column header shows a sort control, but without scripts clicking one does nothing.
  • Long lists: in the product every row is shown, with no pagination (open branch 8). The prototype cuts the post-mortem reports and the flows cost table short and marks the cut with an italic row.
  • Not drawn: no in-page section index (open branch 6). Flow IDs, story titles and people are plain text, not links (open branch 7). Only the final two-tab state is shown, not the transition period (open branch 9).
  • Look: the colours, type and components approximate Halo's current UI and reuse the header and palette of the other prototypes in this repository. Halo's frontend source was not available to this step, so the Design step checks the components, colours and fonts against the live app (A7).
  • Out of scope: there is no "Full dashboard" tab, no people/team page and no "Underwriting users vs Everyone" filter. Team is McKinsey or Internal, taken from the sign-in email, and is read-only everywhere.
