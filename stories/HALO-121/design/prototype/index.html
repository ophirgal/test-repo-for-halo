HALO-121 · PROTOTYPE

Role-based sidebar, View all page and the wide card

A clickable walk-through of the main paths in the approved journey. My Work shows each "View as" role only what it acts on. It has no "Backlog" or "Active sprint" headers, is wider (360px, was 288px), and its cards keep the title on the first row with the status tags in the bottom-right corner. A View all button stays pinned under the list and opens a page with Active, Not Started and Archived tabs. The Not Started rows end with a "Start in Jira" link on the Harel instance and a one-click Start button on Halo-developer instances. Everything outside these screens looks as it does today. The colours, type and spacing are Halo's own tokens (tokens.css), and the dashed "Prototype" strip on each page is not part of the design.

Choices made in this prototype

  • Switching roles. "View as" lives in the expanded navigation today, so each page has a dashed Prototype strip for switching between PO, Dev and PO and Dev. The same strip switches between the Harel and Halo-developer instances on Not Started.
  • Which stories go under an epic in the PO and Dev list. Every non-archived story of the epic, started or not, assigned to anyone (open branch 1 of the structure).
  • Search, Status and Sort on View all. The page has its own controls, shared across its three tabs (open branch 3).
  • While View all is open. The View all button looks selected and no card in the sidebar is highlighted (open branch 6).
  • The one-click button. It is labelled Start, and its tooltip says what it does in Jira. The walk-through follows HALO-143, whose Jira status has no direct transition to In Progress, so the failure path is a realistic one.
  • Restore, but no Delete. Today's code offers only Archive and Restore on the list ("Archive and restore are the only removals", epicBatchModel.ts), so the Archived tab carries Restore only. FR-14 asks for "the same actions available today", which this keeps. The PRD's mention of "delete" does not match today's product.
