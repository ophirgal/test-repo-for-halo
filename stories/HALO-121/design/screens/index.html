HALO-121 · DESIGN · SCREEN SET

Role-based sidebar, View all page and the wide card

Every screen of the approved structure in each of its states, as a desktop page and a phone page side by side. They follow the approved prototype's layout, flow and sample content. Colours, type and spacing are Halo's own tokens from src/index.css, in the shared tokens.css. The only token that changes is --panel-w, from 288px to 360px. Each page links on to the next screen in the journey and has a "← Gallery" link back here.

Choices made in this set

  • Phone layout. Halo has no phone layout today: the narrowest width the workspace is tested at is 900px. On a phone:
    • the icon rail becomes a top bar with the project name;
    • My Work fills the screen, with View all still pinned at the bottom;
    • View all is its own page with "‹ My Work" back;
    • table rows stack as cards, and every action is at least 40–44px tall;
    • dialogs open as bottom sheets.
  • Loading. The sidebar keeps the product's own three-dot loader (halo-workspace-panel__loading). The new View all tabs use skeleton rows shaped like their columns.
  • Errors. They keep the product's habit of stating the cause with its request id, so the line can be found in the backend logs. Retry leads to the loading state.
  • Restore, but no Delete. As in the approved prototype: today's list offers only Archive and Restore (epicBatchModel.ts), so the Archived tab carries Restore only.
  • Empty states. This set uses the copy from the structure's open branch 5, plus a new no-jira-board state for a project with no Jira board.
  • Wide card states. They are shown in the Dev list: selected (HALO-121 open), picked (two cards, with today's "2 selected · Clear" strip) and hover (⋯ visible). The combined view's epic and story shading is on the PO and Dev page.
