Choices made in this screen set
  • Layout: concept B, unchanged. On desktop, the context pane (Back link, stepper, heading) is on the left and the action pane on the right. On mobile the panes stack with the context first, and the stepper names only the current step.
  • Errors are never shown by colour alone: each error has an icon, bold text, a 2 px red border on the field and a hidden “Error:” prefix for screen readers. The error is tied to its field with aria-describedby, and the field is marked aria-invalid. Error red is #b3261e, which has a 6.5:1 contrast ratio on white.
  • Focus: the first field in error gets autofocus, and the page draws its focus ring so you can see where focus lands. Focus order is Back, Name, Email, then Submit, on every page.
  • Several errors at once: each message sits under its own field, as the structure describes. AC 2 lists one error per state, so the gallery draws them one at a time.
  • Submitting: the button is grey, has aria-disabled and shows a spinner; the spinner stops when the visitor asks for reduced motion. The fields are read-only, the form has aria-busy, and a status line is announced to screen readers.
  • Submission failed: a role="alert" message above the form gives the cause and the way out (“select Submit again”). The values are kept.
  • No scripts: on every form page, “Submit” is a link to the confirmation, so you can keep clicking through the journey.
  • Site page footer: the prototype’s “User Journey” link was only there for reviewing the prototype, so it is dropped. The product footer has only “Newsletter”.
  • Colours, type and spacing are in the shared tokens.css, copied from the prototype. Mobile pages use the same file, with <body class="mobile"> instead of media queries.
